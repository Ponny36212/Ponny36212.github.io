1. 学习目标与案例说明

本文以一个名为 git-study-demo 的练习仓库为主线，模拟以下学习过程：

  1. 在本地创建仓库
  2. 添加文件并提交版本
  3. 查看修改、撤销修改、回退版本
  4. 创建功能分支并合并回主分支
  5. 连接远程仓库并推送代码
  6. 学会区分 fetch、pull、push
  7. 了解常见辅助命令与日常实践

1.1 本文重点关注的核心技术点

  • Git 的三区模型：工作区、暂存区、本地仓库
  • 常用基础命令：init、status、add、commit、log、diff
  • 版本回退与撤销：restore、reset、revert、reflog
  • 分支开发：branch、switch、merge
  • 远程协作：remote、push、pull、fetch、clone
  • 辅助能力：stash、tag、.gitignore

1.2 命令行学习建议

学习 Git 时，建议每次执行命令都问自己两个问题：

  • 这个命令影响了哪个区域？工作区、暂存区，还是本地仓库？
  • 这个命令执行后，Git 的“状态”发生了什么变化？

只有把“状态变化”看清楚，Git 才会真正学懂。

2. Git 基础认知

2.1 Git 是什么

Git 是一个分布式版本控制系统，用于记录文件的历史变化，并支持多人协作开发。

2.2 Git 中最重要的三个区域

  • 工作区（Working Directory）：你当前正在编辑的文件目录
  • 暂存区（Staging Area）：准备进入下一次提交的内容缓冲区
  • 本地仓库（Local Repository）：已经通过 commit 保存下来的历史版本

6. 管理历史版本：log、reset、revert、reflog

6.1 查看更清晰的提交图

执行后核心变化

  • 仅查看历史
  • 会以更直观的图形方式展示提交关系和分支结构

6.2 git reset：移动当前分支指针

先假设当前有两个提交：

方式一：软回退

执行后核心变化

  • 当前分支从提交 B 回到提交 A
  • 原本 B 中的改动仍保留在暂存区
  • 适合“想重写提交说明”或“重新整理提交内容”

方式二：默认回退（mixed）

执行后核心变化

  • 当前分支从提交 B 回到提交 A
  • 暂存区被清空回到 A 的状态
  • B 的修改还保留在工作区

方式三：硬回退

执行后核心变化

  • 当前分支回退到 A
  • 暂存区和工作区都会回到 A 的状态
  • 最近一次提交以及对应修改都会被丢弃
  • 风险较高，使用前应确认改动是否还需要

6.3 git revert：创建一个“反向提交”

执行后核心变化

  • Git 不会直接删除原提交
  • 它会新增一个提交，用于抵消指定提交的影响
  • 适合已经推送到远程的历史版本回滚
  • 团队协作中更安全

6.4 git reflog：找回误操作历史

执行后核心变化

  • 显示 HEAD 的移动历史
  • 即使 reset --hard 之后，也有机会通过 reflog 找回之前的位置
  • 当你误删提交、误切分支时非常有用

6.5 找回误删提交案例

执行后核心变化

  • 仓库状态被恢复到你指定的历史位置
  • 可以重新找回看似“消失”的提交

9. fetch、pull、push 的区别

9.1 可视化对比图

9.2 git fetch

执行后核心变化

  • 从远程仓库下载最新提交信息
  • 更新远程跟踪分支，例如 origin/main
  • 不会自动修改当前分支，也不会直接改动工作区

典型使用场景

  • 先看看远程有什么变化
  • 评估是否需要合并
  • 想先保持本地代码稳定

9.3 git pull

执行后核心变化

  • 先执行 fetch
  • 再把远程更新合并到当前分支
  • 工作区和当前分支会一起更新
  • 如果本地也改过同一部分内容，可能触发冲突

典型使用场景

  • 想快速同步远程最新代码并继续开发

9.4 git push

执行后核心变化

  • 将本地新提交上传到远程仓库
  • 远程分支历史会向前推进
  • 本地工作区内容本身不会因 push 发生变化

13.1 基础命令

目标 命令 核心作用
撤销工作区修改 git restore <file> 恢复文件内容

查找误操作历史 git reflog 查看 HEAD 变动

14. 学习建议与实践建议

14.1 推荐学习顺序

建议你按下面顺序练习：

  1. git init、git status、git add、git commit
  2. git diff、git restore、git log
  3. git branch、git switch、git merge
  4. git remote add、git push -u、git fetch、git pull
  5. git reset、git revert、git reflog
  6. git stash、git tag、.gitignore

14.2 每次练习都建议保留四个观察动作

  • 暂存区里有什么内容
  • 历史提交到了什么位置
  • 本地分支与远程分支是否已经建立跟踪关系

14.4 最后总结

掌握 Git 的关键，不在于死记命令，而在于理解“命令会让仓库状态发生什么变化”。
建议你边看本文边实际敲一遍命令，最好建立一个自己的练习仓库，把每一步都执行一次。

  • git add 到底把什么放进了哪里？

  • 切换分支时，为什么文件内容会变化？
  • fetch、pull、push 各自影响的是哪一部分？
